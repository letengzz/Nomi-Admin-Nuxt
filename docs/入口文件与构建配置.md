# 入口文件与构建配置

本文档详细解析项目的入口文件和构建配置，包括 `main.ts`、`App.vue`、`vite.config.ts` 和 `tsconfig.json`。

## 1. 应用入口 — `src/main.ts`

**文件路径：** `src/main.ts`
**功能：** 创建并初始化 Vue 应用实例，按顺序完成所有核心模块的注册。

### 1.1 完整代码解析

```typescript
// 导入根组件 App.vue
import App from './App.vue'
// 导入 Vue 的 createApp 工厂函数
import { createApp } from 'vue'
// 导入 Pinia Store 初始化函数（状态管理）
import { initStore } from './store'
// 导入 Vue Router 初始化函数（路由管理）
import { initRouter } from './router'
// 导入 i18n 国际化实例
import language from './locales'
// 导入 TailwindCSS 样式（原子化 CSS 框架）
import '@styles/core/tailwind.css'
// 导入全局 SCSS 样式入口
import '@styles/index.scss'
// 导入控制台输出工具（自定义控制台欢迎信息）
import '@utils/sys/console.ts'
// 导入全局自定义指令注册函数（v-auth / v-roles 等）
import { setupGlobDirectives } from './directives'
// 导入全局错误处理函数
import { setupErrorHandle } from './utils/sys/error-handle'
```

**导入顺序说明：**

1. 首先导入 Vue 框架和根组件
2. 然后导入核心模块初始化函数（Store / Router / i18n）
3. 接着导入全局样式（TailwindCSS + SCSS）
4. 最后导入工具函数（控制台 / 指令 / 错误处理）

### 1.2 移动端触摸兼容

```typescript
// 监听 touchstart 事件，设置 passive: false 以允许 preventDefault
// 解决某些移动端浏览器的触摸事件默认行为问题
document.addEventListener(
  'touchstart',
  function () {},
  { passive: false }
)
```

**为什么需要这段代码：** 某些移动端浏览器（如 iOS Safari）在 `touchstart` 事件上默认使用 `passive: true`，导致无法调用 `preventDefault()`。这里显式设置为 `false`，确保后续可以阻止默认的触摸行为（如滚动穿透）。

### 1.3 应用初始化流程

```typescript
// 第一步：创建 Vue 应用实例
const app = createApp(App)

// 第二步：初始化 Pinia 状态管理
// 注册 Pinia 实例和持久化插件
initStore(app)

// 第三步：初始化 Vue Router 路由系统
// 注册路由实例、配置前置/后置守卫
initRouter(app)

// 第四步：注册全局自定义指令
// 包括 v-auth（权限指令）、v-roles（角色指令）等
setupGlobDirectives(app)

// 第五步：设置全局错误处理
// 捕获 Vue 组件渲染错误和全局 JavaScript 错误
setupErrorHandle(app)

// 第六步：注册国际化插件
// 配置 i18n，支持中英文切换
app.use(language)

// 第七步：挂载应用到 DOM
// 将 Vue 应用挂载到 index.html 中的 #app 元素
app.mount('#app')
```

**初始化顺序图：**

```
createApp(App)
    ↓
initStore(app)          → Pinia + persistedstate
    ↓
initRouter(app)         → Vue Router + 守卫
    ↓
setupGlobDirectives(app) → v-auth / v-roles
    ↓
setupErrorHandle(app)   → 全局错误捕获
    ↓
app.use(language)       → Vue I18n
    ↓
app.mount('#app')       → 挂载到 DOM
```

## 2. 根组件 — `src/App.vue`

**文件路径：** `src/App.vue`
**功能：** 作为 Vue 应用的根组件，提供全局配置和初始化逻辑。

### 2.1 模板部分

```html
<template>
  <!-- ElConfigProvider: Element Plus 全局配置组件 -->
  <ElConfigProvider
    size="default"                    <!-- 全局组件尺寸：默认 -->
    :locale="locales[language]"       <!-- Element Plus 国际化语言 -->
    :z-index="3000"                   <!-- 弹出层起始 z-index -->
    :card="{
      shadow: 'never'                 <!-- 卡片组件默认不显示阴影 -->
    }"
  >
    <!-- RouterView: 路由视图，渲染当前匹配的组件 -->
    <RouterView></RouterView>
  </ElConfigProvider>
</template>
```

**ElConfigProvider 说明：**
- `size="default"`：设置所有 Element Plus 组件的默认尺寸
- `:locale`：根据用户语言设置动态切换 Element Plus 的国际化文本
- `:z-index="3000"`：设置弹出组件（Dialog/Drawer/Popover 等）的起始层级
- `:card="{ shadow: 'never' }"`：全局配置卡片组件不显示阴影

### 2.2 脚本部分

```typescript
<script setup lang="ts">
  // 导入用户状态 Store（获取当前语言设置）
  import { useUserStore } from './store/modules/user'
  // 导入 Element Plus 中文语言包
  import zh from 'element-plus/es/locale/lang/zh-cn'
  // 导入 Element Plus 英文语言包
  import en from 'element-plus/es/locale/lang/en'
  // 导入系统升级检测工具
  import { systemUpgrade } from './utils/sys'
  // 导入 CSS 过渡动画控制工具
  import { toggleTransition } from './utils/ui/animation'
  // 导入存储兼容性检测工具
  import { checkStorageCompatibility } from './utils/storage'
  // 导入主题初始化函数
  import { initializeTheme } from './hooks/core/useTheme'

  // 获取用户 Store 实例
  const userStore = useUserStore()
  // 使用 storeToRefs 获取响应式的语言引用
  const { language } = storeToRefs(userStore)

  // Element Plus 语言映射表
  const locales = {
    zh: zh,   // 中文
    en: en    // 英文
  }

  // 组件挂载前：初始化主题和启用过渡动画
  onBeforeMount(() => {
    toggleTransition(true)     // 启用 CSS 过渡动画
    initializeTheme()          // 初始化主题（应用保存的主题或跟随系统）
  })

  // 组件挂载后：检查兼容性、关闭过渡动画、检查系统升级
  onMounted(() => {
    checkStorageCompatibility()  // 检查 localStorage 兼容性
    toggleTransition(false)      // 关闭初始化的过渡动画（防止首次加载闪烁）
    systemUpgrade()              // 检查版本升级，执行数据迁移
  })
</script>
```

### 2.3 生命周期流程

```
onBeforeMount
  ├── toggleTransition(true)    → 启用页面过渡动画
  └── initializeTheme()         → 应用主题设置（亮色/暗色/跟随系统）

onMounted
  ├── checkStorageCompatibility() → 检测浏览器存储支持情况
  ├── toggleTransition(false)    → 关闭初始化过渡（避免首次渲染闪烁）
  └── systemUpgrade()            → 版本升级检测与数据迁移
```

### 2.4 设计要点

1. **主题无闪烁**：在 `onBeforeMount` 中初始化主题，确保 DOM 渲染前主题已就绪
2. **过渡动画控制**：先启用再关闭过渡动画，防止首次加载时出现不必要的动画效果
3. **响应式语言切换**：通过 `storeToRefs` 获取响应式引用，语言变更时自动更新 UI

## 5. 设计思路与架构决策

### 5.1 main.ts 初始化顺序设计

> 为什么必须按照 Store → Router → Directives → ErrorHandle → i18n 的顺序初始化？

**依赖链分析：**

```
initStore()    → Router 守卫中需要访问 Store（登录状态/权限）
   ↓
initRouter()   → 依赖 Store 已初始化（守卫中读取 userStore.isLogin）
   ↓
setupGlobDirectives() → 依赖 Store 已初始化（v-auth 读取权限数据）
   ↓
setupErrorHandle() → 依赖 Router 已初始化（错误跳转需要路由）
   ↓
app.use(language) → 依赖 Store 已初始化（语言设置从 userStore 读取）
   ↓
app.mount()    → 所有插件就绪后再挂载，避免渲染时插件未就绪
```

**如果顺序错误会怎样：**

| 错误场景 | 后果 |
|---------|------|
| Router 在 Store 之前初始化 | 守卫中 `useUserStore()` 报 Pinia 未初始化错误 |
| mount 在 Router 之前 | `<RouterView>` 组件无法匹配路由 |
| Directives 在 Store 之前 | `v-auth` 指令无法读取权限数据 |

### 5.2 App.vue 主题无闪烁策略

> 主题切换时如何避免“白屏闪烁”？

**实现流程：**

```
① onBeforeMount 阶段（DOM 未渲染）
   ├── toggleTransition(true) → 全局禁用 CSS 过渡（* { transition: none }）
   └── initializeTheme() → 直接设置 HTML class 和 CSS 变量
                ↓
② 浏览器渲染第一帧（已经应用了正确的主题）
                ↓
③ onMounted 阶段（DOM 已渲染）
   ├── toggleTransition(false) → 恢复 CSS 过渡
   └── systemUpgrade() → 版本升级检测
```

**关键技巧：**
- `toggleTransition` 通过动态创建/删除 `<style>` 标签实现全局过渡控制
- 在 DOM 渲染前设置主题，用户看到的第一帧就是正确的主题色
- 双层 `requestAnimationFrame` 确保浏览器完成样式计算后再恢复过渡

### 5.3 Vite 插件体系设计思路

> 为什么选择这些插件？每个插件解决了什么问题？

| 插件 | 解决的问题 | 效果 |
|------|---------|------|
| `AutoImport` | 每次使用 `ref`/`computed` 都需要手动 import | 直接使用，无需 import |
| `Components` | Element Plus 组件全量导入导致包体积大 | 按需导入，减少 70%+ 体积 |
| `ElementPlus` | 需要自定义 Element Plus SCSS 主题变量 | 支持 `useSource: true` 深度定制 |
| `viteCompression` | 生产环境传输体积大 | Gzip 压缩，体积减少 60%+ |
| `vueDevTools` | 开发时调试 Vue 组件困难 | 集成 DevTools 面板 |
| `tailwindcss` | CSS 样式编写效率低 | 原子化 class，无需写 CSS 文件 |

### 5.4 构建优化策略

> 生产环境构建做了哪些优化？效果如何？

| 优化策略 | 配置 | 效果 |
|---------|------|------|
| Terser 压缩 | `drop_console` + `drop_debugger` | 去除调试代码，减少 10-15% 体积 |
| Gzip 预压缩 | `>10KB` 的文件生成 `.gz` | Nginx 直接返回压缩文件，传输体积减少 60%+ |
| 依赖预构建 | `optimizeDeps.include` | 开发服务器启动速度提升 3-5 倍 |
| 动态导入 | `src/views/**/*.vue` | 每个页面独立 chunk，首屏加载减小 |
| ES2015 目标 | `build.target: 'es2015'` | 兼容 IE11 等旧浏览器 |

**依赖预构建的设计思路：**

> Vite 开发服务器使用 ESM 原生模块加载，每个 import 都是一个 HTTP 请求。像 ECharts、Element Plus 这种包含上百个模块的库，如果每次都实时转换，会导致页面加载缓慢。预构建将这些模块提前打包为单个 ESM 文件，一个 HTTP 请求即可加载完成。

### 5.5 CSS 全局变量注入设计

> 为什么使用 `additionalData` 全局注入 SCSS 变量？

```scss
// 所有 .vue 和 .scss 文件中可以直接使用这些变量，无需手动 @import
$--color-primary: #5D87FF;
@mixin flex-center { display: flex; align-items: center; justify-content: center; }

// 使用示例
.my-component {
  color: $--color-primary;
  @include flex-center;
}
```

**效果：**
- 所有组件共享同一套设计令牌（Design Token）
- 修改一处变量，全局生效
- 避免每个文件都写 `@import` 导入语句
- Element Plus 的 SCSS 变量可以被项目变量覆盖，实现深度主题定制
