# 状态管理

本文档详细解析基于 Pinia 的状态管理方案，包含 5 个 Store 模块。

---

## 1. Pinia 初始化 — `src/store/index.ts`

**文件路径：** `src/store/index.ts`
**功能：** 创建 Pinia 实例，配置持久化插件。

### 1.1 核心代码

```typescript
import { createPinia } from 'pinia'
import { createPersistedState } from 'pinia-plugin-persistedstate'
import { StorageKeyManager } from '@/utils/storage/storage-key-manager'

export const store = createPinia()

// 创建存储键管理器实例
const storageKeyManager = new StorageKeyManager()

// 配置持久化插件
store.use(
  createPersistedState({
    // 版本化存储键：sys-v{version}-{storeId}
    key: (storeId: string) => storageKeyManager.getStorageKey(storeId),
    storage: localStorage,
    serializer: {
      serialize: JSON.stringify,
      deserialize: JSON.parse
    }
  })
)

// 初始化函数
export function initStore(app: App<Element>): void {
  app.use(store)
}
```

### 1.2 持久化策略

- **存储键格式：** `sys-v3.0.2-setting`、`sys-v3.0.2-user` 等
- **版本化目的：** 应用升级时可通过版本号变化触发数据迁移
- **存储介质：** localStorage
- **序列化：** 使用 JSON.stringify/parse

### 5.4 核心方法

#### `openTab(tab)` — 打开或激活标签

```
openTab(tab)
  ├── 从 keepAliveExclude 中移除（恢复缓存）
  ├── 按路由名称查找（解决动态路由参数问题）
  ├── 未找到 → 按路径查找
  ├── 都不存在 → 新增标签
  │     ├── 固定标签 → 插入到固定标签末尾
  │     └── 普通标签 → 追加到末尾
  └── 已存在 → 更新现有标签（path/params/query/title 等）
```

#### `removeTab(path)` — 关闭标签

```
removeTab(path)
  ├── 检查标签是否存在
  ├── 检查是否固定标签（固定标签不可关闭）
  ├── 从 opened 中移除
  ├── 添加到 keepAliveExclude（清除缓存）
  ├── 如果无标签 → 跳转首页
  └── 如果关闭的是当前标签 → 激活相邻标签
```

#### 批量关闭方法

| 方法 | 说明 |
|------|------|
| `removeLeft(path)` | 关闭左侧所有可关闭标签 |
| `removeRight(path)` | 关闭右侧所有可关闭标签 |
| `removeOthers(path)` | 关闭其他所有可关闭标签 |
| `removeAll()` | 关闭所有可关闭标签（保留固定标签和首页） |

#### `toggleFixedTab(path)` — 切换固定状态

固定标签会被移到所有固定标签的末尾，取消固定则移到固定标签之后。

#### `validateWorktabs(router)` — 验证标签路由有效性

遍历所有标签，检查路由是否仍然有效（动态路由可能已被移除），自动清理无效标签。

## 8. 设计思路与实现方式

### 8.1 Pinia 持久化插件的架构设计

> 为什么选择 `pinia-plugin-persistedstate` 而不是自己写 localStorage？

**设计思路：**

自己写 localStorage 存储需要处理以下问题：
- 序列化/反序列化
- 存储时机（何时保存、何时读取）
- 部分字段持久化（不是所有状态都需要保存）
- 跨版本兼容性

`pinia-plugin-persistedstate` 解决了以上所有问题，且与 Pinia 深度集成，只需在 Store 定义中加一个 `persist` 配置项即可。

**实现方式：**

```typescript
// 每个 Store 只需添加 persist 配置即可自动持久化
export const useSettingStore = defineStore('settingStore', () => {
  // ... 状态和方法
}, {
  persist: {
    key: 'setting',          // 存储键（会被 StorageKeyManager 包装为版本化键）
    storage: localStorage    // 存储介质
  }
})
```

**效果：**
- 任何状态变化自动保存到 localStorage
- 页面刷新后自动恢复上次的状态
- 版本升级时自动使用新的存储键

### 8.2 Setting Store 的设计模式

> 451 行的 Store 是如何保持可维护性的？

**设计思路：**

Setting Store 采用**状态 + 计算属性 + 方法**的三层架构：

```
状态层（ref）：30+ 个配置项，每个都有明确的默认值
    ↓
计算属性层（computed）：5 个派生状态
  ├── getMenuTheme → 根据主题类型返回对应的样式配置
  ├── isDark → 判断是否为暗色模式
  ├── getMenuOpenWidth → 拼接 px 单位
  ├── getCustomRadius → 拼接 rem 单位
  └── isShowFireworks → 判断节日烟花状态
    ↓
方法层：25+ 个操作方法，每个方法都是纯函数式的状态修改
  ├── switchMenuLayouts() → 切换菜单布局
  ├── setGlopTheme() → 设置全局主题
  ├── setElementTheme() → 设置 Element Plus 主题色
  └── reload() → 触发页面刷新
```

**关键设计决策：**
- 每个配置项都有独立的 toggle 方法（如 `setButton()`、`setCrumbs()`），而不是通用 setter
- `setGlopTheme` 同时更新 theme 和 themeMode，并同步到 localStorage（非持久化字段，用于快速读取）
- `setCustomRadius` 除了更新状态，还直接设置 CSS 变量（`--custom-radius`）

### 8.3 Worktab Store 的标签页缓存策略

> 569 行的标签页 Store 如何管理 KeepAlive 缓存？

**设计思路：**

标签页关闭后，如果组件被 `<KeepAlive>` 缓存了，它仍然会占用内存。必须在关闭标签时将组件名称加入 `keepAliveExclude` 列表，让 `<KeepAlive>` 自动销毁缓存。

**实现方式：**

```typescript
// 关闭标签时的缓存处理
const removeTab = (path: string) => {
  const targetTab = getTab(path)

  // 1. 从标签列表中移除
  opened.value.splice(targetIndex, 1)

  // 2. 将组件名称加入缓存排除列表
  if (targetTab?.name) {
    addKeepAliveExclude(targetTab) // keepAliveExclude.push(tab.name)
  }

  // 3. 如果关闭的是当前标签，激活相邻标签
  if (current.value.path === path) {
    const newIndex = targetIndex >= opened.value.length
      ? opened.value.length - 1 : targetIndex
    current.value = opened.value[newIndex]
    safeRouterPush(current.value)
  }
}
```

**效果：**
- 关闭标签页后，对应的组件缓存被自动销毁，释放内存
- 重新打开同一标签时，组件会重新创建和加载数据
- 固定标签页（`fixedTab: true`）不可被关闭

**标签页复用策略：**
- 先按路由名称（`name`）查找，再按路径（`path`）查找
- 动态路由参数变化时复用同一标签（如 `/user/1` 和 `/user/2` 共用一个标签）
- 查询参数变化时同样复用标签，只更新参数

### 8.4 User Store 的登出清理策略

> 登出时如何确保所有状态都被正确清理？

**设计思路：**

登出是一个复杂的操作，需要清理多个 Store 的状态、移除动态路由、重置路由守卫状态，并跳转到登录页。

```
登出流程：

① 保存当前用户 ID（用于下次登录时判断是否为同一用户）
       ↓
② 清空用户状态
  ├── info = {}
  ├── isLogin = false
  ├── isLock = false
  ├── accessToken = ''
  └── refreshToken = ''
       ↓
③ 清理关联资源
  ├── sessionStorage.removeItem('iframeRoutes')
  ├── menuStore.setHomePath('')
  └── resetRouterState(500) → 500ms 后注销动态路由
       ↓
④ 跳转到登录页（携带 redirect 参数）
```

**智能标签页清理：**

```typescript
// 下次登录时检查是否为同一用户
const checkAndClearWorktabs = () => {
  const lastUserId = localStorage.getItem('lastUserId')
  const currentUserId = info.value.userId

  if (String(currentUserId) !== lastUserId) {
    // 不同用户登录，清空标签页
    worktabStore.opened = []
    worktabStore.keepAliveExclude = []
  }
  // 同一用户重新登录，保留标签页
}
```

**效果：**
- 同一账号重新登录：保留之前的标签页状态
- 不同账号登录：清空标签页，防止数据泄露
- 登出后动态路由被注销，无法访问需要权限的页面
